# Evgeny.dev

Статическое портфолио на React, TypeScript и Vite. Backend и секретный API-ключ для работы сайта не нужны.

## Установка и проверки

Используйте Node **22.12+** (проверено на 24.21.0) и npm **11.19.0**. Единственный актуальный lockfile — `package-lock.json`; не смешивайте npm и Bun. Версии прямых зависимостей закреплены на проверенных версиях, а не обновлены до latest.

```sh
npm ci --ignore-scripts
npm test
npm run lint
npm run build
npm run dev
```

`lint` выполняет строгий TypeScript typecheck с noUnusedLocals/noUnusedParameters; ESLint в проект не добавлен. `build` всегда включает typecheck. `npm run clean` удаляет **только** `dist` переносимым Node-скриптом. Исходные PNG и пользовательские настройки не удаляются. `.vs` исключена из version control, локальные файлы IDE остаются на месте.

Tailwind сканирует только `src` и `index.html`, поэтому тексты отчётов/тестов не меняют production CSS. Настройка источников соответствует [официальной документации Tailwind](https://tailwindcss.com/docs/detecting-classes-in-source-files).

Если Windows не позволяет заменить занятый native-модуль в node_modules, завершите свой запущенный dev-server перед `npm ci`. Не отключайте проверки и не удаляйте пользовательские файлы для обхода блокировки.

## Развёртывание

Скопируйте `.env.example` в `.env.local` и задайте реальные публичные настройки. Значения `VITE_` входят в клиентскую сборку и **не должны содержать секретов**.

- `VITE_SITE_URL`: публичный URL сайта с подкаталогом и завершающим `/`, если он есть. Используется для абсолютных Open Graph/canonical URL.
- `VITE_BASE_PATH`: необязательное переопределение пути публикации; по умолчанию берётся pathname из `VITE_SITE_URL`, без обоих значений используется `/`.
- `VITE_CONTACT_FORM_ENDPOINT`: необязательный HTTP(S) endpoint формы; без него используется явный сценарий подготовки письма и открытия почтового клиента. Сам сайт письма не отправляет.
- `VITE_TELEGRAM_URL`: необязательная замена существующей Telegram-ссылки.

После настройки выполните `npm run build` и разместите содержимое `dist` в соответствующем подкаталоге. Сервер должен отдавать JS/CSS/изображения с корректными MIME types. Рекомендуется HTTPS. Без `VITE_SITE_URL` локальная сборка использует относительный URL изображения соцсетей: перед публикацией нужен фактический публичный адрес. В репозитории домен не выдуман.

Изображение соцсетей — `public/assets/social-preview.png`, 1200×630. Для пересоздания из текущего портрета: `node scripts/generate-social-preview.cjs` (нужен Playwright/Chrome). Оптимизированные display-assets можно пересоздать `python scripts/optimize_images.py` с Pillow. PNG-оригиналы сохраняются; фотографии портрета экспортируются в WebP quality 94, остальные основные изображения — lossless WebP.

## Браузерные регрессии

Playwright закреплён как dev-зависимость; он не входит в клиентский bundle. Используйте установленный Chrome через `CHROME_PATH` или установите отдельный Chromium командой `npx playwright install chromium`.

Пример для PowerShell:

```powershell
$env:CHROME_PATH = 'C:\Program Files\Google\Chrome\Application\chrome.exe'
npm run build
npm run test:browser
```

На системах с установленным Playwright Chromium `CHROME_PATH` не нужен. Для использования внешнего runtime задайте `PLAYWRIGHT_MODULE_PATH` абсолютным путём к модулю Playwright. `QA_OUTPUT` меняет папку доказательств (по умолчанию системная временная папка).

Тесты исполняют неизменённый production bundle в Chrome через локальную подачу файлов Playwright (`route.fulfill`), без зависимости от доступности localhost и реальных внешних сервисов. Проверяются 320×568, 390×844, 844×390, 1440×900, 1920×1080, диалоги/фокус/wheel, изображения, storage, GitHub fallback, HUD/resize/reduced motion. GitHub mock и намеренные сетевые ошибки детерминированы; настоящие письма/публикации не выполняются. Проверка реального deployed origin, CSP/TLS/CORS и Safari остаётся отдельным шагом.

Для проверки подкаталога соберите с `VITE_BASE_PATH=/preview/` и запустите browser-script с `QA_BASE=/preview/`. Для проверки абсолютных OG URL дополнительно задайте тестовый или действительный `VITE_SITE_URL`, соответствующий этому пути. После проверки верните окружение к фактическим deployment-настройкам и пересоберите.

## Состояние и восстановление

GitHub кешируется отдельно для каждого username. Валидный кеш v4 читается как offline fallback без удаления; новые snapshots атомарно сохраняются в v5. При сетевом отказе сохраняется последний успешный каталог. Ограничение пагинации — 10 страниц с явным предупреждением; при достижении лимита ранее сохранённые проекты сохраняются.

Портрет хранится одной записью с фильтром; legacy-ключи остаются читаемыми. Обложки имеют единый источник состояния в App и прежние совместимые ключи. Reset сохраняет tombstone, чтобы старые alias-записи не возвращались после перезагрузки. При отказе storage сайт работает в памяти и явно сообщает, что изменения не переживут reload. Произвольные пользовательские данные автоматически не удаляются.

Новые загрузки принимают PNG/JPEG/WebP/GIF/AVIF до 5 МБ и 24 мегапикселей. Битые файлы отклоняются; устаревшие/отменённые операции не заменяют актуальный выбор. Крупные статичные изображения ограничиваются по стороне 1600px и сжимаются; GIF сохраняет анимацию. Сохранение может быть отклонено квотой браузера с понятным предупреждением.

История аудита: `PROJECT_AUDIT.md`; выполненные изменения и ограничения — `PROJECT_FIX_REPORT.md`, повторная оценка — `PROJECT_AUDIT_AFTER.md`.

## English / Русский

Локализация работает без дополнительных зависимостей: словари находятся в `src/i18n/locales/en.json` и `ru.json`, механизм — в `src/i18n/index.ts`. Исходные английские строки служат ключами; названия проектов и технологий сохраняются. Ранее русскоязычные подробные описания проектов также получили английские версии.

Приоритет: сохранённый ручной выбор `evgeny_portfolio_language_v1` → первый поддерживаемый язык в `navigator.languages` / `navigator.language` → English. Неподдерживаемые предпочтения пропускаются. Автоматический выбор не записывается поверх ручного. Ранний скрипт в `index.html` выставляет `html[lang]` до отображения интерфейса; React сразу использует тот же язык. Отказ localStorage не мешает переключению в текущем посещении.

EN / RU в навигации меняет контент, доступные подписи и метаданные без перезагрузки. Состояние формы, каталога и редакторов сохраняется, а навигационная GSAP-анимация пересоздаётся для нового набора символов. URL остаётся прежним: у этого SPA нет отдельных языковых страниц, поэтому фиктивные hreflang-ссылки не добавляются. Статический HTML для поисковых роботов остаётся английским; клиент обновляет title, description и Open Graph.

Шрифты размещены локально в `public/assets/fonts`, правила — в `public/fonts.css`. Латиница сохраняет Instrument Serif, Plus Jakarta Sans, Newsreader и JetBrains Mono. Для кириллицы используются Cormorant Garamond и Golos Text, моноширинный шрифт — прежний JetBrains Mono. WOFF2-файлы ограничены диапазонами символов и загружаются по необходимости; лицензии OFL находятся рядом. Размеры, веса, межстрочные и межбуквенные интервалы сохранены.

Проверка локализации после сборки: `npm run test:i18n:browser` (тот же `CHROME_PATH`, что и у основного браузерного набора). Она проверяет оба языка на 320, 375, 768, 1024, 1440 и 1920 px, первое появление текста, сохранение языка, ошибки формы, состояние окон, прокрутку, Unicode-анимацию и реально используемые шрифты для всех 66 русских букв через Chrome DevTools Protocol. Скриншоты сохраняются вне репозитория в `QA_OUTPUT` или временный каталог ОС.

Интерфейс, локальный каталог, шаблоны и статусы GitHub переведены. Описания новых сторонних репозиториев, не представленных в словарях, остаются на языке автора; для них можно добавить переводы в словари. Внешний сервис автоматического перевода не используется.
