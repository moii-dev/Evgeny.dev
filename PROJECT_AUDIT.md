## High

### BUG-001 — Запрет localStorage приводит к белому экрану

**Критичность:** High. **Статус:** Подтверждена.

**Расположение:** `src/App.tsx:36–42`, начальные значения `photoUrl` и `isMonochrome`; `src/main.tsx:5`.

**Описание:** Исключение при чтении настроек портрета прерывает рендер всего приложения.

**Причина:** `localStorage.getItem` вызывается в useState initializer без try/catch; границы обработки ошибки рендера нет.

**Последствия:** Весь сайт недоступен в контексте, где storage запрещён политикой браузера/встраивания, хотя сайт способен работать без сохранения настроек.

**Воспроизведение:** До загрузки страницы заставить `Storage.prototype.getItem` бросать SecurityError. Chrome: пустое содержимое body, `pageerror: Storage denied`.

**Решение:** Безопасный storage-adapter с fallback на исходные настройки; обработка исключений чтения. Error boundary как дополнительная защита.

**Риски исправления:** Низкие; проверить прежние сохранённые настройки и режим без storage.

### BUG-002 — Валидный JSON неправильной структуры из кеша обрушает каталог

**Критичность:** High. **Статус:** Подтверждена.

**Расположение:** `src/services/githubService.ts:20–27`, `src/App.tsx:49–53`, `src/components/AllProjectsModal.tsx:27–31`.

**Описание:** Доверие к JSON.parse как к `Project[]` допускает объекты без обязательных полей в React state.

**Причина:** TypeScript-аннотация не выполняет runtime-валидацию. Проверяется только TTL, синтаксически корректные данные не проверяются по схеме.

**Последствия:** Ошибка `Cannot read properties of undefined (reading 'toLowerCase')` и белый экран при открытии каталога. Повторяется до истечения TTL или очистки кеша.

**Воспроизведение:** Установить `evgeny_portfolio_github_repos_v4` в `[{}]`, timestamp — текущее время; перезагрузить и открыть All projects. Воспроизведено браузером и прямым вызовом сервиса.

**Решение:** Проверять массив и каждое используемое поле; некорректный кеш игнорировать/удалять, использовать локальный каталог и обновлять сетью.

**Риски исправления:** Низкие; корректно обработать старые версии схемы и optional-поля.

### BUG-003 — Детали проекта открываются под общим каталогом

**Критичность:** High. **Статус:** Подтверждена.

**Расположение:** `src/App.tsx:135–151`, `src/components/AllProjectsModal.tsx:59,145–150`, `src/components/ProjectModal.tsx:70`.

**Описание:** Нажатие карточки в All projects создаёт ProjectModal, но видимым остаётся каталог.

**Причина:** `allProjectsOpen` не закрывается при выборе проекта; оба overlay имеют z-50, каталог расположен позже в DOM и перекрывает детали.

**Последствия:** Основная функция Details в полном списке выглядит неработающей. Одновременно существуют два overlay и конфликтующие состояния фокуса/прокрутки.

**Воспроизведение:** All projects → FreeChat. Кнопка Close modal появляется в DOM, но скриншот показывает только каталог. Escape закрывает скрытые детали, не каталог.

**Решение:** Явная модель modal stack либо переход catalog → details с закрытием каталога и предусмотренным возвратом к его фильтрам/позиции.

**Риски исправления:** Средние: возврат в список, сохранение поиска, focus restoration и закрытие Escape.

### BUG-004 — Lenis перехватывает прокрутку модальных окон

**Критичность:** High. **Статус:** Подтверждена.

**Расположение:** `src/hooks/useScrollNavigation.ts:77–94`; `src/components/ProjectModal.tsx:26–38,70–71`; `src/components/AllProjectsModal.tsx:59–60,143`.

**Описание:** Колесо над прокручиваемыми деталями перемещает страницу позади overlay, внутреннее содержимое остаётся неподвижным.

**Причина:** Глобальный Lenis с smoothWheel работает во время overlay. Нет stop/start и исключения вложенных scroll-container через prevent/data-lenis-prevent/настройки nested scroll. `body.style.overflow='hidden'` не останавливает программное перемещение окна Lenis.

**Последствия:** Пользователь не может привычно дочитать детали/список; теряется позиция фоновой страницы.

**Воспроизведение:** Открыть WorldBox-React, wheel +500 над содержимым. При scrollHeight 943 и clientHeight 898 внутренний scrollTop остался 0, window.scrollY изменился 727 → 1217.

**Решение:** Единый менеджер overlay: останавливать фоновый Lenis и разрешать native scroll содержимого; корректно восстанавливать состояние после последнего окна.

**Риски исправления:** Средние: touch, несколько overlay, textarea, сохранение scroll position.

### BUG-006 — Gamma Cleaner теряет локальные метаданные после синхронизации

**Критичность:** Medium. **Статус:** Подтверждена.

**Расположение:** `src/services/githubService.ts:51–53,76–95`; `src/data/featuredProjects.ts:222–244`.

**Описание:** Реальное имя репозитория не совпадает ни с id, ни с отображаемым title локальной записи.

**Последствия:** После ответа API исчезают локальное длинное описание, логотип и категория; меняется id, следовательно ранее сохранённая пользовательская обложка перестаёт находиться.

**Решение:** Хранить явный repoName/full_name и объединять по нему; предусмотреть совместимость storage-ключей.

**Риски исправления:** Средние: миграция id, дедупликация и ранее сохранённые обложки.

### BUG-007 — Сетевой сбой удаляет live-каталог из UI и маскируется как успешная синхронизация

**Критичность:** Medium. **Статус:** Подтверждена.

**Расположение:** `src/services/githubService.ts:116–122`; `src/App.tsx:45–66`; `src/components/ProjectsSection.tsx:64`.

**Описание:** При неудачном refresh сервис возвращает ALL_LOCAL_PROJECTS вместо последнего успешного набора. App игнорирует `error` и выставляет fromCache=false принудительно.

**Причина:** В модели результата не разделены live, cache и fallback, а ошибка не доходит до видимого состояния.

**Последствия:** Добавленные GitHub-проекты пропадают при временном отказе/лимите API; посетитель не понимает причину, tooltip сообщает Sync with GitHub вместо признака fallback.

**Воспроизведение:** Получить успешный ответ с новым Other, затем fetch → throw Error('offline'), refresh. Other исчезает, error не виден, tooltip — `Sync with GitHub`. Подтверждено.

**Решение:** Сохранять last-known-good набор, использовать просроченный кеш как fallback, показывать ошибку/источник данных и время последней успешной синхронизации.

**Риски исправления:** Средние: согласование загрузки, повторов и кеша.

### BUG-008 — Сетевые операции не имеют ограниченного времени ожидания

**Критичность:** Medium. **Статус:** Подтверждена.

**Расположение:** `src/services/githubService.ts:34–44`; `src/App.tsx:45–66`; `src/components/ContactSection.tsx:88–118`.

**Описание:** Незавершённый запрос оставляет Sync, а при настроенном endpoint и контактную форму, в состоянии loading без собственного способа отмены.

**Причина:** Нет AbortController/deadline; завершение loading зависит только от settle fetch. Браузерные транспортные тайм-ауты не являются заданным UX-дедлайном приложения.

**Последствия:** Обновление недоступно неопределённое время; поля формы при соответствующей конфигурации заблокированы.

**Воспроизведение:** Задержать ответ GitHub без resolve/reject: refresh остаётся disabled. Для контактного endpoint аналогичный сценарий следует из того же кода; реальный endpoint сейчас не задан.

**Решение:** Ограниченный timeout, отмена и понятный retry; не очищать пользовательский ввод при тайм-ауте.

**Риски исправления:** Средние: медленная сеть, различение отмены и ошибки, исключение повторной отправки сообщения.

### BUG-009 — Cancel и Reset портрета сохраняют устаревший черновик

**Критичность:** Medium. **Статус:** Подтверждена.

**Расположение:** `src/components/PhotoChangeModal.tsx:25–29,51–53,164–166,175–179`; `src/App.tsx:76–80,153–162`.

**Описание:** После закрытия и повторного открытия показываются ранее несохранённые previewPhoto/mono. После Reset старое изображение можно сразу вернуть через Save & Apply.

**Причина:** Компонент постоянно смонтирован; useState(currentPhoto) выполняется один раз, открытие и изменение props не синхронизируют черновик.

**Последствия:** Cancel не отменяет изменения в следующей сессии редактирования, Reset визуально противоречив и легко перезаписывается.

**Воспроизведение:** Изменить URL → Cancel → открыть: preview сохраняется. Reset → открыть → Save: сброшенный портрет заменяется старым. Все переходы подтверждены.

**Решение:** Инициализировать черновик из актуальных props при каждом открытии, сбрасывать inputUrl; определить commit/cancel lifecycle.

**Риски исправления:** Низкие; не сбрасывать текущий черновик при постороннем ререндере App.

### BUG-010 — Ошибка сохранения портрета не обработана

**Критичность:** Medium. **Статус:** Подтверждена.

**Расположение:** `src/App.tsx:69–80`; `src/components/PhotoChangeModal.tsx:51–54,164–166`.

**Описание:** При quota/security error состояние уже обновлено, но запись/удаление storage падает и последующий onClose не выполняется.

**Причина:** setItem/removeItem без try/catch, неатомарное обновление состояния и двух storage-ключей.

### BUG-019 — Неограниченная и неконтролируемая загрузка изображений

**Критичность:** Medium. **Статус:** Вероятна.

**Расположение:** `src/components/PhotoChangeModal.tsx:31–41,44–48`; `src/components/ProjectModal.tsx:42–56`.

**Описание:** Весь файл читается в data URL без лимита байтов/разрешения, проверки декодирования, error/abort и защиты от устаревшего результата. Произвольный URL портрета можно сохранить до проверки загрузки.

**Причина:** accept=image/* используется как единственная подсказка выбора; FileReader не управляется как отменяемая операция.

**Последствия:** Большие файлы увеличивают память, base64 и синхронную запись storage; быстрый выбор A → B может завершиться поздним onload(A), заменившим B. Несуществующий URL сохраняет сломанный портрет без fallback в Hero.

**Решение:** Лимит размера и пикселей, проверка decode, resize/compression; request generation id/abort; понятные ошибки. Для больших бинарных данных рассмотреть IndexedDB.

**Риски исправления:** Средние: качество/ориентация снимков, SVG/GIF и совместимость старого storage.

## Безопасность и устойчивость: дополнительные результаты

- Действующие секреты в проверенных прикладных исходниках и корневых конфигурациях не обнаружены. `.env.example` содержит placeholders; реальных `.env` среди видимых корневых файлов нет, `.env*` исключены из Git. Публичные контактные адреса не трактовались как утечка секретов и намеренно не перепечатывались.
- В runtime-коде нет eval, dangerouslySetInnerHTML или ручного HTML-встраивания внешних описаний. React выводит описания как текст. Подтверждённый XSS/SQL injection/path traversal не найден. Серверных файловых операций и SQL здесь нет.
- `repo.homepage`/URL из кеша используются как href без явного allowlist протоколов. Это потенциальная граница доверия, но успешный вредоносный сценарий не доказан: GitHub может ограничивать homepage, React/браузер — схемы URL. Не классифицируется как подтверждённая эксплуатируемая уязвимость. При исправлении схемы данных разумно разрешить только http/https для внешних ссылок.
- Внешние target=_blank ссылки используют noreferrer либо noopener noreferrer; оснований утверждать reverse-tabnabbing по этим ссылкам нет.
- Серверной авторизации/проверки прав нет, поскольку серверных операций нет. Настройки фото принадлежат локальному посетителю, не являются редактированием владельцем сайта для всех. Если задумана публичная CMS, её реализация отсутствует, но такое требование не следует из кода.
- Контактная форма без endpoint честно показывает подготовку письма и требует отдельного открытия почтового клиента. Это частичная mailto-функциональность, не подтверждённая отправка; отсутствие backend само по себе не объявляется багом. Реальная доставка, CORS, anti-spam, server-side validation и retention внешнего endpoint не проверены.
- GitHub — публичный API без токена. Rate limiting и 403/429 возможны; непосредственная ошибка приложения в таком случае описана BUG-007. При текущем отказе сервис возвращает локальные 14 проектов, поэтому базовое offline-портфолио не исчезает, если само приложение уже загружено.
- Кеш JSON парсится в guarded try/catch, сетевой сервис перехватывает fetch/parse ошибки. Главные разрывы защиты — schema validation и чтение/запись портрета в App. Некорректный API payload в большинстве случаев уходит в fallback, а неправильный кеш может попасть в React.
- В hook есть cleanup resize/keydown, gsap context, ticker и Lenis.destroy. Подтверждённая неограниченная утечка listeners/timelines не найдена. Блокировки многопоточного кода и deadlock неприменимы к отсутствующим worker/backend-механизмам. Возможна конкуренция асинхронных чтений FileReader (BUG-019), но она не выдается за доказанный race.
- ContactSection использует короткие setTimeout без cleanup; при быстром уходе/перемонтировании возможен устаревший callback. Длительная утечка памяти этим не доказана; отдельная критичная проблема не назначена.
- Header на каждом scroll считывает rect до пяти секций; анимации постоянно используют глобальный ticker. Размер страницы мал, CPU/батарея не профилировались, поэтому это точки последующего измерения, а не доказанные зависания.
- Шрифты загружаются с Google Fonts, три фотографии About — с Unsplash, avatar preset — с GitHub. Для About предусмотрен SVG fallback. Для основного портрета onError fallback отсутствует (см. BUG-019). Сетевая доступность, privacy headers и политика подключения внешних ресурсов должны оцениваться на целевом хостинге.
- CSP, HSTS, cache headers, frame restrictions, компрессия CDN и TLS не представлены конфигурацией deployment и не проверены. Их отсутствие в Vite-коде не доказывает отсутствие на хостинге.
- На 390×844 ширина документа равнялась 390px: глобальный горизонтальный overflow в проверенной начальной раскладке не воспроизведён. Форма, длинные имена репозиториев, 200% zoom, программные клавиатуры и все мобильные браузеры не покрыты полностью.

## Архитектурные выводы

1. Разделение sections, данных, сервиса и геометрии в целом соответствует масштабу портфолио. Переписывание на другой framework, обязательный backend или глобальный state manager не требуется для решения найденных дефектов.
2. Наиболее дорогой недостаток — несколько независимых источников истины: ProjectModal/ProjectCover/storage для обложек; App/PhotoChangeModal для портрета; React classes/GSAP inline style для HUD. Ошибки проявляются на переходах между компонентами.
3. Overlay не образуют единую систему. Уровни z-index, Escape, focus и scroll lock определяются локально, а Lenis глобален. Поэтому компоненты по отдельности рендерятся, но совместный пользовательский поток не работает.
4. GitHub merge смешивает identity, порядок отображения, curated content и сетевые поля. Сопоставление по title/id и последующая дедупликация теряют как live-данные, так и локальный контент.
5. Навигация дублируется: NAVIGATION_SECTIONS в config, отдельный массив в Header, прямые native scrollIntoView в About/Contact. Это не требует абстракций ради SOLID, но единые scroll/motion правила уменьшат конкретные рассогласования.
6. Проект зависит от внешней сети и браузерного storage без общей модели ошибок и источников данных. Отсутствует deadline/retry UI, last-known-good и схема storage.
7. Проверка под названием lint не ловит hook/accessibility/style проблемы; build не включает явную последовательную typecheck-стадию. Отсутствие тестов не доказывает ошибки, но найденные межмодульные дефекты сейчас не защищены от повторения.
